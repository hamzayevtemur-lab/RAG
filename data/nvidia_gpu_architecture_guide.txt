2. HOPPER ARCHITECTURE (H100 / H200) DEEP DIVE
================================================================================
The NVIDIA H100 Tensor Core GPU, based on the Hopper architecture, was the flagship accelerator
for AI training and inference throughout fiscal years 2023 and 2024.

2.1 Streaming Multiprocessor (SM) Design
The H100 contains 132 Streaming Multiprocessors (SMs), of which 114 are hardware-enabled in the
SXM5 form factor (8 SMs are disabled for yield optimization). Each SM includes:
- 128 FP32 CUDA Cores (total: 14,592 active CUDA Cores)
- 4 Fourth-Generation Tensor Cores (total: 456 active Tensor Cores)
- 256 KB of combined L1 data cache / shared memory (configurable split)
- 1 new Tensor Memory Accelerator (TMA) unit for asynchronous bulk data movement

2.2 Fourth-Generation Tensor Cores
The fourth-generation Tensor Cores introduce native FP8 (E4M3 and E5M2 formats) precision.
FP8 enables the Transformer Engine, which dynamically selects between FP8 and FP16 precision
on a per-layer, per-tensor basis during training. This doubles throughput compared to FP16
Tensor Core operations with minimal loss in model convergence quality.

Performance Comparison (per GPU, SXM5 form factor):
Operation Precision           H100 Peak TFLOPS     A100 Peak TFLOPS     H100 vs A100 Speedup
---------------------------------------------------------------------------------------------
FP64                          33.5                  19.5                  1.7x
FP32                          66.9                  19.5                  3.4x
TF32 (Tensor Core)            494.7                 156.0                 3.2x
FP16 / BF16 (Tensor Core)     989.4                 312.0                 3.2x
FP8 (Tensor Core)             1,978.9               N/A                   N/A (new capability)
INT8 (Tensor Core)             1,978.9               624.0                 3.2x

2.3 High Bandwidth Memory (HBM3 and HBM3e)
The H100 SXM5 ships with 80GB of HBM3 memory across 5 active HBM3 stacks, delivering
3,350 GB/s of aggregate memory bandwidth. Each HBM3 stack consists of 8 DRAM dies vertically
bonded using Through-Silicon Via (TSV) interconnects.

The H200, announced in November 2023, upgrades the memory subsystem to 141GB of HBM3e across
6 active stacks, increasing bandwidth to 4,800 GB/s. This provides:
- 76% more memory capacity than H100 (141GB vs 80GB)
- 43% more memory bandwidth (4,800 vs 3,350 GB/s)
- Enables inference of larger language models (e.g., Llama 2 70B) without tensor parallelism

HBM3e memory is supplied by SK Hynix (primary), Samsung Electronics, and Micron Technology.
SK Hynix achieved mass production of 8-high HBM3e stacks in Q1 2024, with each stack delivering
1.2 TB/s bandwidth at 9.8 Gbps per pin. SK Hynix's 12-high HBM3e (36GB per stack) is expected
to begin mass production in Q3 2024, targeted for the Blackwell B200 GPU.

2.4 Transformer Engine
The Transformer Engine is a co-designed hardware-software feature unique to Hopper. It uses
per-tensor dynamic scaling factors stored in FP32 to automatically convert activations, weights,
and gradients between FP8 and FP16 during each layer's forward and backward passes.

The scaling algorithm operates as follows:
1. During the forward pass of layer L, compute the maximum absolute value of the output tensor.
2. Derive an FP32 scaling factor that maps the tensor's dynamic range into the FP8 representable range.
3. Store this scaling factor in a per-tensor metadata header.
4. During the subsequent forward/backward pass, use the stored scaling factor to quantize inputs to FP8.
5. Perform the matrix multiplication in FP8, accumulate partial products in FP32.
6. De-quantize the output back to FP16/BF16 for residual connections and normalization layers.

This process is transparent to the model developer. In practice, Transformer Engine FP8 training
achieves accuracy within 0.1% of FP16 baseline on GPT-3 175B, BERT-Large, and ViT-H benchmarks,
while delivering approximately 1.6x to 2.0x speedup on end-to-end training time.

3. BLACKWELL ARCHITECTURE (B100 / B200 / GB200) — NEXT-GENERATION PREVIEW
================================================================================
Announced at GTC 2024 in March 2024, the NVIDIA Blackwell architecture represents the most
significant leap in accelerated computing performance in NVIDIA's history.

3.1 Key Architectural Innovations:
- Second-Generation Transformer Engine with FP4 precision, doubling inference throughput over FP8.
- 208 billion transistors fabricated across two reticle-limited dies connected by a 10 TB/s
  chip-to-chip interconnect on a single unified package (effectively a multi-die GPU).
- 192 GB of HBM3e memory delivering 8,000 GB/s aggregate bandwidth.
- Fifth-Generation NVLink providing 1,800 GB/s bidirectional bandwidth per GPU (1.4x vs Hopper).
- RAS (Reliability, Availability, Serviceability) Engine with dedicated hardware for detecting
  and isolating transient and permanent faults in real-time during training runs.
- Secure AI features including hardware-enforced Confidential Computing and TEE (Trusted Execution
  Environment) extensions for multi-tenant inference deployments.

3.2 Blackwell Product SKUs:

GB200 Superchip Grace + B200      384GB total  2700W  Trillion-parameter model training
GB200 NVL72     72 GPUs + 36 Grace  13.8 TB    120kW  Full-rack exascale AI deployment

4. NVLINK & NVSWITCH INTERCONNECT TOPOLOGY
================================================================================
NVLink is NVIDIA's proprietary high-speed GPU-to-GPU interconnect. Unlike PCIe Gen 5
(128 GB/s bidirectional), NVLink provides dramatically higher bandwidth for collective
communication operations essential to data-parallel and tensor-parallel distributed training.

NVLink Generation Comparison:
Generation          Links/GPU    BW per Link    Total BW/GPU     Supported Architecture
---------------------------------------------------------------------------------------
NVLink 1.0 (2016)   4            40 GB/s        160 GB/s         Pascal P100
NVLink 2.0 (2017)   6            50 GB/s        300 GB/s         Volta V100
NVLink 3.0 (2020)   12           50 GB/s        600 GB/s         Ampere A100
NVLink 4.0 (2022)   18           50 GB/s        900 GB/s         Hopper H100
NVLink 5.0 (2024)   18           100 GB/s       1,800 GB/s       Blackwell B200

4.1 NVSwitch and NVLink Network:
In DGX H100 and HGX H100 systems, four NVSwitch chips (each with 64 NVLink 4.0 ports)
connect 8 H100 GPUs in an all-to-all non-blocking fat-tree topology. Every GPU can
communicate with every other GPU at the full 900 GB/s without contention.

For Blackwell NVL72 rack-scale systems, NVIDIA introduces the NVLink Switch System:
72 Blackwell GPUs connected through 9 NVLink Switch trays, each containing 2 NVLink
Switch chips. This creates a single, fully-connected 72-GPU domain with 130 TB/s of
total bisection bandwidth, enabling trillion-parameter models to train across 72 GPUs
with all-reduce latencies measured in microseconds rather than milliseconds.

5.2 DGX H200 System:
The DGX H200 replaces the H100 GPUs with H200 GPUs (141 GB HBM3e each) while maintaining
the same chassis, CPU, and networking configuration. Total GPU memory per system increases
from 640 GB to 1,128 GB (1.1 TB), enabling larger batch sizes and longer sequence lengths
for LLM training without gradient checkpointing trade-offs.

5.3 DGX SuperPOD:
A DGX SuperPOD is a turnkey AI data center building block consisting of multiple DGX systems
interconnected via a Quantum-2 InfiniBand leaf-spine network fabric.
- Standard Configuration: 32 DGX H100 nodes (256 GPUs) with 2-tier InfiniBand fabric.
- Maximum Configuration: 128 DGX H100 nodes (1,024 GPUs) with 3-tier fat-tree InfiniBand fabric.
- Aggregate FP8 Performance: Up to 1 Exaflop (1,024 x ~1 PFLOP per H100).
- Total HBM Memory: Up to 81,920 GB (80 TB) across 1,024 GPUs.
- SuperPOD Reference Power: Approximately 1.3 MW for a 32-node configuration.

6. INFERENCE OPTIMIZATION STACK: TENSORRT-LLM
================================================================================
TensorRT-LLM is NVIDIA's open-source library for optimizing large language model inference
on NVIDIA GPUs. It compiles transformer architectures into highly optimized CUDA kernels.

6.1 Key Optimization Techniques:
1. Quantization: INT4 AWQ, GPTQ, FP8, INT8 SmoothQuant weight-activation quantization.
2. KV-Cache Management: Paged attention (inspired by vLLM's PagedAttention) with dynamic
   memory allocation to minimize GPU memory fragmentation during batched inference.
3. In-Flight Batching (Continuous Batching): New requests are inserted into running batches
   without waiting for the entire batch to complete, reducing tail latency by up to 5x.
4. Tensor Parallelism (TP): Splitting weight matrices across multiple GPUs along hidden
   dimensions, enabling models larger than single-GPU memory to serve at low latency.
5. Pipeline Parallelism (PP): Distributing transformer layers across GPU stages for
   throughput-optimized offline batch processing.
6. Speculative Decoding: Using a smaller draft model to generate candidate tokens, then
   verifying them in parallel with the full model. Achieves 2-3x tokens/sec improvement
   for latency-bound single-request inference.

7. THERMAL DESIGN AND POWER DELIVERY
================================================================================
Data center GPU thermal management has become a critical constraint as TDP (Thermal Design
Power) has escalated from 300W (A100) to 700W (B100) to 1000W (B200).

GPU TDP Evolution:
Architecture        GPU SKU        TDP (Watts)     Cooling Solution Required
---------------------------------------------------------------------------
Ampere              A100 SXM       400W            Air-cooled heatsink
Hopper              H100 SXM5      700W            Air-cooled (with high-flow chassis)
Hopper              H200 SXM5      700W            Air-cooled (with high-flow chassis)
Blackwell           B100 SXM       700W            Air-cooled
Blackwell           B200 SXM       1000W           Direct liquid cooling (mandatory)
Blackwell           GB200 NVL72    ~120kW/rack     Direct liquid cooling (full rack)

The GB200 NVL72 rack-scale system produces approximately 120 kW of thermal energy in a single
42U server rack, which is 10-12x the power density of a traditional enterprise server rack
(10-12 kW). This mandates direct-to-chip liquid cooling infrastructure using warm water
(typically 35-45°C inlet temperature) circulated through cold plates mounted directly on GPU
and CPU packages. Facility-level cooling distribution units (CDUs) reject the collected heat
to the building's chilled water loop or dry coolers.

Data center operators planning Blackwell NVL72 deployments must provision:
- Electrical: 150 kW per rack (including networking and overhead) at 480V three-phase.
- Cooling: 120+ kW liquid cooling capacity per rack, with rear-door heat exchangers or
  in-row CDUs rated for 45°C return water temperature.
- Floor Loading: Approximately 2,500 kg per rack (5,500 lbs), requiring reinforced raised
  floor or slab construction.
- Network: 72x 400 Gb/s InfiniBand or 800 Gb/s Ethernet ports per rack.
